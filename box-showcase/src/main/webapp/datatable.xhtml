b:datatable

Tabela com paginação, ordenação e filtro por coluna, tudo resolvido no backend — cada interação dispara um postback que chama de novo o método carregar(...) da fonte de dados. Nenhuma linha fica guardada entre requisições: só primitivos de controle (página, campo/direção de ordenação, filtros digitados) vão pro estado da view, o que faz o componente funcionar bem mesmo com datasets grandes demais pra carregar inteiros de uma vez.

Fonte de dados

O atributo value aponta pra um objeto que implementa DatatableLazyModel<T> — normalmente o próprio bean. Cada chamada de carregar(DatatableConsulta) recebe o offset/tamanho da página, o campo/direção de ordenação e os filtros (campo → texto digitado) e devolve uma DatatablePage<T> (linhas da página + total de registros). O tamanho de página pode vir do atributo linhasPorPagina (útil quando o próprio bean controla, ex.: um seletor construído fora do componente) ou, se omitido, do método linhasPorPaginaPadrao() da própria interface — este exemplo usa esse segundo caminho.

Atributos — b:datatable

AtributoObrigatórioDescrição
valueSimA fonte de dados (DatatableLazyModel<T>).
varSimNome que expõe a linha atual em EL pros filhos das colunas (igual ao var do h:dataTable).
linhasPorPaginaNãoTamanho da página. Sem valor, usa modelo.linhasPorPaginaPadrao().
converterNãoNecessário só pro evento select — converte a linha clicada num id (e de volta) sem guardar a linha em nenhum lugar. Normalmente um Converter gerenciado por CDI (ver exemplo abaixo).
ordenarPorPadraoNãoCampo usado como ordenação inicial, antes de qualquer clique num cabeçalho.
ordenarAscendentePadraoNãoDireção da ordenação inicial. Padrão true.

Atributos — b:column

AtributoObrigatórioDescrição
fieldNãoPropriedade lida do objeto de linha (var) e enviada ao backend como chave de ordenação/filtro. Sem filhos na coluna, também define o que é exibido na célula.
headerNãoRótulo do cabeçalho. Sem valor, usa o próprio field.
sortableNãoSe true, clicar no cabeçalho ordena por essa coluna (nenhum → asc → desc → nenhum). Padrão false.
filterableNãoSe true, mostra um campo de texto abaixo do cabeçalho pra filtrar por essa coluna. Padrão false.

Facets

FacetDescrição
headerBloco acima da tabela — título, contador, barra de ações.
footerBloco abaixo da paginação — normalmente ações em lote.
emptySubstitui o corpo da tabela quando a página atual não tem nenhuma linha (tipicamente por causa de um filtro). Sem essa facet, a tabela só fica com o cabeçalho e a paginação mostra "Nenhum registro".

Client behaviors (f:ajax aninhado)

EventoDispara quando
pageclica num botão de paginação
sortclica num cabeçalho ordenável
filtersai de um campo de filtro (ou aperta Enter) depois de mudar o valor
selectclica numa linha — evento default, não re-renderiza a tabela sozinho

Exemplo

<b:datatable value="\#{bean}" var="item" converter="\#{pessoaConverter}">
    <f:facet name="header">
        <h2>Pessoas</h2>
    </f:facet>
    <b:column field="nome" header="Nome" sortable="true" filterable="true"/>
    <b:column field="email" header="E-mail" filterable="true"/>
    <b:column field="cargo" header="Cargo" sortable="true" filterable="true"/>
    <b:column field="dataAdmissao" header="Admissão" sortable="true"/>
    <f:facet name="empty">Nenhuma pessoa encontrada com esse filtro.</f:facet>
    <f:ajax event="select" listener="\#{bean.aoSelecionar}" render=":resultado"/>
</b:datatable>
