b:datatable

b:datatable

Table with pagination, sorting and per-column filtering, all resolved on the backend — every interaction triggers a postback that calls the data source's load(...) method again. No row stays kept between requests: only control primitives (page, sort field/direction, typed filters) go into the view state, which lets the component work well even with datasets too large to load in full.

Data source

The value attribute points to an object that implements DatatableLazyModel<T> — usually the bean itself. Each call to load(DatatableQuery) receives the page offset/size, the sort field/direction and the filters (field → typed text) and returns a DatatablePage<T> (the page's rows + total record count). The page size can come from the pageSize attribute (useful when the bean itself controls it, e.g. a selector built outside the component) or, if omitted, from the interface's own defaultPageSize() method — this example uses that second path.

Attributes — b:datatable

AttributeRequiredDescription
valueYesThe data source (DatatableLazyModel<T>).
varYesName that exposes the current row in EL to the column children (same as h:dataTable's var).
pageSizeNoPage size. Without a value, uses model.defaultPageSize().
converterNoOnly needed for the select event — converts the clicked row into an id (and back) without keeping the row anywhere. Usually a CDI-managed Converter (see example below).
defaultSortByNoField used as the initial sort, before any header click.
defaultSortAscendingNoInitial sort direction. Default true.

Attributes — b:column

AttributeRequiredDescription
fieldNoProperty read from the row object (var) and sent to the backend as the sort/filter key. Without children in the column, also defines what's shown in the cell.
headerNoHeader label. Without a value, uses field itself.
sortableNoIf true, clicking the header sorts by this column (none → asc → desc → none). Default false.
filterableNoIf true, shows a text field below the header to filter by this column. Default false.

Facets

FacetDescription
headerBlock above the table — title, counter, action bar.
footerBlock below pagination — usually bulk actions.
emptyReplaces the table body when the current page has no rows (typically because of a filter). Without this facet, the table just keeps the header, and pagination shows "No records".

Client behaviors (nested f:ajax)

EventFires when
pagea pagination button is clicked
sorta sortable header is clicked
filterleaving a filter field (or pressing Enter) after changing its value
selecta row is clicked — default event, doesn't re-render the table on its own

Example

<b:datatable value="\#{bean}" var="item" converter="\#{personConverter}">
    <f:facet name="header">
        <h2>People</h2>
    </f:facet>
    <b:column field="name" header="Name" sortable="true" filterable="true"/>
    <b:column field="email" header="Email" filterable="true"/>
    <b:column field="role" header="Role" sortable="true" filterable="true"/>
    <b:column field="hireDate" header="Hire date" sortable="true"/>
    <f:facet name="empty">No people found for this filter.</f:facet>
    <f:ajax event="select" listener="\#{bean.onSelect}" render=":resultado"/>
</b:datatable>
