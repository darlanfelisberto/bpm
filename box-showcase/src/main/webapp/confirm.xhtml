b:confirm

Inline confirmation (popup near the clicked element, without blocking the thread like the browser's native confirm()) before proceeding with an action. Two ways to use it, without conflict between them on the same page.

1. As a behavior, nested inside an h:commandLink

b:confirm is a ClientBehavior: it goes inside any ActionSource2 (h:commandLink, h:commandButton), just like f:ajax. Supports EL — the message can reference the row variable (\#{item} below), re-evaluated for each row even inside h:dataTable.

Attributes

AttributeRequiredDescription
messageYesText shown in the popup. Accepts EL.
<h:commandLink action="\#{bean.delete(item)}" styleClass="link-danger">
    Delete
    <b:confirm message="Delete \#{item}?"/>
    <f:ajax render=":formBehavior"/>
</h:commandLink>
ItemActions
#{item} Delete

2. As a plain attribute, without a Faces component

For when it doesn't even make sense to have a Faces component/behavior: just the data-box-confirm attribute on any link or button already gets the confirmation, picked up by a generic listener already included on the page (confirm.js). Uses fewer server resources (no extra component state), but doesn't accept EL directly in the attribute — pass the already-resolved text via p:data-box-confirm.

<h:commandLink action="\#{bean.delete(item)}" styleClass="link-danger"
               p:data-box-confirm="Delete \#{item}?">
    Delete
    <f:ajax render=":formAtributo"/>
</h:commandLink>
ItemActions
#{item} Delete
