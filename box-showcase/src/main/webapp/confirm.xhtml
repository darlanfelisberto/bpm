b:confirm

b:confirm

Confirmação inline (popup perto do elemento clicado, sem bloquear a thread como o confirm() nativo do navegador) antes de seguir com uma ação. Duas formas de usar, sem conflito entre elas na mesma página.

1. Como behavior, aninhado num h:commandLink

b:confirm é um ClientBehavior: entra dentro de qualquer ActionSource2 (h:commandLink, h:commandButton), igual ao f:ajax. Suporta EL — a mensagem pode referenciar a variável da linha (\#{item} abaixo), reavaliada a cada linha mesmo dentro de h:dataTable.

Atributos

AtributoObrigatórioDescrição
mensagemSimTexto exibido no popup. Aceita EL.
<h:commandLink action="\#{bean.excluir(item)}" styleClass="link-danger">
    Excluir
    <b:confirm mensagem="Excluir \#{item}?"/>
    <f:ajax render=":formBehavior"/>
</h:commandLink>
ItemAções
#{item} Excluir

2. Como atributo puro, sem componente Faces

Pra quando nem faz sentido ter um componente/behavior Faces: só o atributo data-box-confirm em qualquer link ou botão já ganha a confirmação, pego por um listener genérico já incluído na página (confirmar.js). Menos recurso de servidor (nenhum estado extra de componente), mas não aceita EL direto no atributo — passe o texto já resolvido via p:data-box-confirm.

<h:commandLink action="\#{bean.excluir(item)}" styleClass="link-danger"
               p:data-box-confirm="Excluir \#{item}?">
    Excluir
    <f:ajax render=":formAtributo"/>
</h:commandLink>
ItemAções
#{item} Excluir
